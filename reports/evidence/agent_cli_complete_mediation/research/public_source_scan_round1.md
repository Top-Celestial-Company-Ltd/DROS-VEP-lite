## Scope and status

- Protocol: `PROTO-AGENT-CLI-COMPLETE-MEDIATION-2026-v1.0`
- Scan date / access date: `2026-09-22` (Asia/Taipei)
- Scope: OpenAI Codex CLI, Claude Code, Gemini CLI, Cursor, OpenHands; Linux Landlock, AppArmor/LSM, BPF-LSM, seccomp, OCI/container runtime, and IPE.
- Source rule: official security/sandbox documentation, official source code, official CVE/security advisories, and original papers only. Secondary commentary, community issue discussion, and marketing-only material are excluded from the registry below.
- Live testing: **not performed**.
- Current research status: `INSUFFICIENT_PUBLIC_EVIDENCE` for complete mediation across a general Agent-CLI topology. This is not evidence that any named product is insecure.

This is a candidate source registry for the first public scan, not a product ranking and not a complete security assessment. `Supports execution topology` identifies the topology that the source directly describes or constrains; it does not mean that the source proves complete coverage of that topology.

## Evidence-level key

- `E1` — official documentation/specification
- `E2` — official source code or implementation documentation in the project repository
- `E3` — official security advisory/CVE
- `E4` — original academic paper or author-hosted primary record

Topology codes follow the frozen protocol: `ET-01` direct process creation, `ET-02` execveat, `ET-03` child process, `ET-04` shell-mediated execution, `ET-05` interpreter-mediated execution, `ET-06` script execution, `ET-07` alternate executable/path resolution, `ET-08` environment inheritance, `ET-09` hooks/configuration-triggered execution, `ET-10` runtime/container transition, `ET-11` JIT/anonymous executable memory, `ET-12` indirect process creation, `ET-13` inherited execution context, `ET-14` external-effect transition.

## Round-1 findings and bounded interpretations

### 1. What the public sources do support

1. **Product-specific execution boundaries exist.** Codex, Claude Code, Gemini CLI, Cursor, and OpenHands each publish a boundary around at least one execution surface: shell/tool commands, child processes, a container runtime, a local sandbox backend, or a cloud-agent VM.
2. **The enforcement mechanisms are heterogeneous and topology-dependent.** The sources describe bubblewrap, Seatbelt, Landlock, seccomp, Docker/OCI namespaces, AppArmor/LSM profiles, BPF-LSM hooks, and VM/container boundaries. Their scope, prerequisites, defaults, and fallback behavior differ.
3. **Approval/policy is not the same as OS enforcement.** Gemini policy rules, Claude Code permission rules, and Cursor run modes are tool-call or approval controls. They may complement an OS sandbox but do not by themselves establish kernel-level complete mediation.
4. **Capability presence is not enforcement evidence.** AppArmor requires a loaded profile; BPF-LSM requires a loaded and attached program; Landlock requires a ruleset and supported ABI; seccomp requires a filter; OCI requires a configured runtime and host policy; IPE requires a policy and integrity provider.
5. **The sources themselves expose material escape/fallback/limitation conditions.** The Codex and Claude Code advisories document version-scoped boundary failures; Claude Code and Gemini documentation document fallback/expansion modes; OpenHands documentation warns about writable mounts and deployment exposure.

### 2. What this scan does not support

- No source supports `COMPLETE_MEDIATION_ESTABLISHED` for a general AI-agent CLI topology.
- No source supports a universal claim that any named product is `SAFE`, `SECURE`, `UNSAFE`, or `INSECURE`.
- No source supports host-wide coverage of all `execve`, `execveat`, child, shell, interpreter, script, path-resolution, hook/configuration, container-transition, inherited-context, and external-effect paths for any product in scope.
- No source supports the claim that sandboxing, seccomp, Landlock, AppArmor, BPF-LSM, OCI containers, or IPE alone is a complete Agent authorization system.
- No source supports the claim that absence of public evidence proves absence of enforcement.
- No source supports the claim that one advisory proves system-wide insecurity, or that one successful enforcement path proves complete mediation.
- This round does not support any DROS-specific integration or universal-governance claim.
