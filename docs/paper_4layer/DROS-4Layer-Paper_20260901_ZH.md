## 摘要 (Abstract)
DROS 是一個將 Agent 身分與聲明之執行權限以密碼學方式綁定至受控二進位 C-ABI 執行路徑的四層執行期基板。在入侵後威脅模型下，透過自主攻擊搜尋、變異測試、獨立 Oracles 與 24 小時浸泡評測，於受評估之觀測邊界內觀測到零未授權物理效應。

**關鍵字 (Index Terms)—** AI Agent 資安、執行期基板、受控 C-ABI 授權邊界、自主對抗評測、RCU 狀態轉換、資訊流控制 (IFC)、歸因治理。

## 一、 緒論與「語意—核心悖論」 (Introduction & The Semantic-Kernel Paradox)

由大型語言模型（LLM）驅動的自主 AI Agent，正迅速從被動的對話助理轉變為被賦予直接工具調用權限的營運實體。在現代企業工作流程中，Agent 能自主規劃多步驟任務、查詢後端關聯式資料庫、修改原始碼庫並做出財務或雲端基礎設施承諾。

然而，這種自主運作引入了根本性的系統架構挑戰：**語意意圖與物理執行權限的深層解耦**。自主 Agent 持有合法憑證、委派的 OAuth Token 與有效 Session 身分，卻在不可信且潛在惡意的外部上下文上進行推理。當攻擊者透過間接提示詞注入（IPI）、目標劫持或多輪對話誘導污染上下文時，傳統周界防禦完全失效，因為所有惡意操作均源自於合法的內部安全主體。

### 1.1 語意—核心悖論 (The Semantic-Kernel Paradox)
現代計算機安全架構在治理自主 Agent 工作負載時展現出結構性的分裂，我們將其定義為**「語意—核心悖論」**：

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                             語意—核心悖論架構對照                            │
├──────────────────────────────────────┬──────────────────────────────────────┤
│ 1. 應用層語意防禦 (高語意、零確定性) │ 2. 作業系統核心沙箱 (高確定性、零語意)│
├──────────────────────────────────────┼──────────────────────────────────────┤
│ • Prompt 防火牆與 JSON 驗證器        │ • Linux Seccomp-BPF、Namespaces、eBPF│
│ • 豐富的自然語言語意理解能力         │ • 二進位確定性系統呼叫過濾           │
│ • 本質上屬於概率性分類               │ • 對 Agent 角色身分完全失明 (Blind)  │
│ • 可透過編碼混淆與注入繞過           │ • 無法分辨共享行程內不同 Agent 的寫入│
└──────────────────────────────────────┴──────────────────────────────────────┘
```

1. **應用層語意防禦（高語意、零確定性）：** LLM 護欄、Prompt 清理器與輸出分類器運作於自然語言語意領域。然而，語意過濾本質上是概率性的：對抗性提示詞突變、多輪上下文投毒與混淆的間接注入，均能以非零概率繞過語意檢查。
2. **作業系統核心沙箱（高確定性、零語意）：** Linux Seccomp-BPF、Namespaces、Landlock 與 eBPF 等底層原語運作於物理領域，能對系統呼叫強制執行二進位准許/拒絕規則。然而，OS 沙箱是**上下文失明（Context-Blind）**的：從核心視角來看，所有操作均源自於相同的宿主行程 PID（例如 Python 直譯器），核心無法分辨特定磁碟寫入是由合法的財務 Agent 所發起，還是由被劫持的客服 Agent 所發起。

我們將此架構漏洞定義為**「Agent 至執行歸因斷層（Agent-to-Execution Attribution Gap）」**：現代架構在結構上無法將 Agent 的語意身分與授權上下文，精確綁定至底層二進位執行路徑。

### 1.2 DROS 基板架構定位與受管轄執行域 (Governed Execution Domain)
DROS（確定性執行期作業系統基板）駐留於應用框架與作業系統之間，建立了一個與宿主隔離原語協同工作的授權平面（Authorization Plane）：

```text
應用框架 (OpenAI Agents, LangGraph, CrewAI, AutoGen)
                      │
                      ▼
┌─────────────────────────────────────────────────────────────┐
│ L1: 偵測智能 (Detective Intelligence - 語意過濾)            │
├─────────────────────────────────────────────────────────────┤
│ L2: 身分零信任 (Identity & Zero Trust - 3-Tier PKI + DIT)   │
├─────────────────────────────────────────────────────────────┤
│ L3: 動態 IFC 治理 (Dynamic IFC - 污染追蹤與帶內遮蔽)        │
├─────────────────────────────────────────────────────────────┤
│ ★ L4: 執行授權閘門 (Execution Gate - 亞微秒點陣圖 C-ABI)   │
└─────────────────────────────┬───────────────────────────────┘
                              │ (受管轄之二進位執行路徑)
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ 宿主 OS 隔離邊界 (Seccomp-BPF / Linux Namespaces / MMU)     │
└─────────────────────────────┬───────────────────────────────┘
                              ▼
宿主作業系統核心與物理端點 (OS Syscall, DB WAL, 檔案系統 I/O)
```

DROS 的核心設計命題在於：**安全性必須被視為在受嚴格管轄之執行域內可實驗證偽的經驗屬性，而非跨越非託管原生代碼路徑的先驗假設**。本文報告的所有保證，均為在儀器觀測空間內經嚴格檢驗的經驗不變量。

### 1.3 四大核心研究問題 (Research Questions)
* **RQ1 (防禦有效性)：** 在入侵後條件下（$C_A = 1$），受管轄的執行路徑能否確定性阻止未授權操作在受管轄域內引發物理狀態轉變？
* **RQ2 (撤銷原子性)：** 在高併發執行與策略動態撤銷的競態下，線性化狀態轉換協議是否會允許過期授權執行？
* **RQ3 (評測敏感度)：** 評測框架與測試基座能否有效偵測蓄意注入的安全性缺陷與編譯器級變異回歸？
* **RQ4 (Oracle 獨立性)：** 授權決策能否由解耦的執行端與物理端觀察者進行客觀且獨立的交叉驗證？

## 二、 威脅模型、評測空間與系統邊界假設

### 2.1 入侵後威脅模型與明確邊界假設 ($C_A = 1$)
本評測建立在嚴格的**入侵後威脅模型**之上，主動假設攻擊者已完全攻破應用層：
* **假設 1 (完全應用層失陷 $C_A = 1$)：** 攻擊者已達成 Prompt 注入、繞過輸入過濾器、竊取系統指令，並在其託管運行容器內掌握對 Agent 應用邏輯的任意執行控制權。
* **假設 2 (持有合法憑證)：** 攻擊者持有合法的 OAuth Token、內部 API Key、資料庫連線字串與已認證的 Session 身分。
* **假設 3 (多代理人協同串通)：** 攻擊者控制多個異質 Agent，試圖透過複雜委派鏈與混淆代理人（Confused Deputy）模式進行特權提升。

#### 明確系統結構假設 (Governed Execution Boundary Hypotheses)
為維持嚴謹的認識論清晰度，避免將使用者空間的 C-ABI 授權與核心層級的物理隔離混為一談，DROS 明確定義四大邊界假設：
* **$H_1$ (受管轄路徑不變量)：** 於所評估之能力類別 $X_{\text{covered}}$ 內的所有特權操作，均強制路由經由 DROS 受控執行路徑。
* **$H_2$ (基板非篡改性)：** 攻擊者無法直接覆寫執行容器內已加載之 DROS 二進位記憶體空間或篡改二進位動態鏈接表。
* **$H_3$ (宿主隔離基礎)：** 宿主核心、硬體 MMU 與基準容器隔離邊界（例如 Seccomp-BPF 阻斷非託管之未受管 Raw Socket/Syscall 逃逸）保持受信任且未被攻破。
* **$H_4$ (範疇邊界)：** 於聲明能力集 $X_{\text{covered}}$ 之外的非託管原始系統操作，明確排除於 C-ABI 授權閘門的經驗安全主張之外。

在上述假設下，DROS 評估在應用層語意推理全面失陷後，帶內確定性授權是否能阻止物理損害。

### 2.2 對照基準與攻擊保真原則 ($A_{B0} = A_{B1}$)
為消除測試負載變異引發的實驗偏差，所有對照實驗嚴格遵守**攻擊保真原則**（$A_{B0} = A_{B1}$ 且 $\text{Env}_{B0} \approx \text{Env}_{B1}$）。

| 拓撲編號 | 拓撲結構 | 主要評測目的 |
| :--- | :--- | :--- |
| **B0 (裸應用)** | `攻擊者 -> 應用程式 -> OS` | 建立未受管 baseline；驗證攻擊負載具備真實破壞力 ($\Delta S_{B0} > 0$)。 |
| **B1 (DROS 啟用)** | `攻擊者 -> 應用程式 -> DROS -> OS` | 主要受測主體；驗證執行遏制能力 ($\Delta S_{B1} \equiv 0$)。 |
| **B2 (縱深防禦)** | `攻擊者 -> 應用 -> DROS+Stack -> OS` | 驗證與現有 EDR、XDR 及 WAF 資安基建的相容性與覆蓋度。 |
| **B3 (純二進位 C-ABI)**| `攻擊者 -> 獨立 C-ABI -> OS` | 在無應用中介層協助下，完全獨立評估 C-ABI 閘門性能。 |

### 2.3 形式化物理效應與安全不變量
物理效應 $I_{\text{physical}}(x)$ 在明確定義的儀器觀測集 $\mathcal{S}_{\text{obs}}$ 上形式化定義：

$$I_{\text{physical}}(x) = \begin{cases} 1, & \exists s \in \mathcal{S}_{\text{obs}}: \Delta(s) > 0 \\ 0, & \forall s \in \mathcal{S}_{\text{obs}}: \Delta(s) = 0 \end{cases}$$

$$\mathcal{S}_{\text{obs}} = \{ \text{核心 Syscall}, \text{檔案系統 Diff}, \text{資料庫 WAL}, \text{行程樹狀態}, \text{出站網路流量}, \text{IPC 狀態} \}$$

**幽靈系統呼叫 (Ghost Syscall)：** 定義為授權決策為 DENY 卻逃逸至宿主核心的系統呼叫。我們強制要求 $G = \#\{ \text{syscall} \mid \text{Auth} = \text{DENY} \land \text{syscall\_observed} = 1 \} = 0$。

系統強制檢驗五大數學安全不變量：
1. **權限非繼承性：** $C_A \centernot\implies C_E$
2. **時序隔離性：** $C_E(t_0) \centernot\implies C_E(t_1) \quad (\forall t_0 \neq t_1)$
3. **能力組合安全性：** $\bigcup_{i=1}^n C_{A_i} \centernot\implies C_E^{\text{unauth}}$
4. **物理遏制不變量：** $\forall x \in X_{\text{covered}}, \; C_A(x) \land \neg C_E(x) \implies I_{\text{physical}}(x) = 0$
5. **狀態零漂移：** $S_{\text{after}} \equiv S_{\text{before}} \quad (\text{在 } \mathcal{S}_{\text{obs}} \text{ 範圍內})$

## 三、 DROS 四層基板具體實作

### 3.1 L1：偵測智能 (Detective Intelligence)
L1 採用啟發式特徵比對與輕量級語意過濾。在 DROS 中，**L1 被明確視為概率性的**。威脅防禦確定性地下沉至 L2–L4；L1 的漏報絕不被視為基板的致命失敗。

### 3.2 L2：身分歸因與動態意圖權證 (Identity & DIT)
L2 建立密碼學三層 PKI 模型（$\text{企業 CA} \rightarrow \text{任務簽發者} \rightarrow \text{臨時工作 Agent}$）並發行「動態意圖權證（DIT）」。每個 DIT 使用 Ed25519 數位簽章將工具名稱、SHA-256 參數哈希、時間戳記與 64 位元能力點陣圖強行綁定。

#### 為什麼 DIT 能解決歸因綁定問題
傳統 Agent 架構將自然語言工具請求直接傳遞給執行端。在 Prompt 注入下，攻擊者可篡改參數或偽冒高權限角色。DIT 透過不可變密碼學封裝消除了此漏洞：
1. **主體解耦：** 執行 Prompt 的 Worker Agent 不具備直接調用工具的權限，僅持有臨時意圖描述符。
2. **簽發者權威：** 僅有經認證的 Task Issuer 組件持有簽署有效 DIT 所需的私鑰。
3. **參數防篡改：** 透過將參數負載的精確 SHA-256 哈希值寫入已簽名 DIT，直譯器下游的任何參數篡改均會使數位簽名失效。
4. **即時撤銷連鎖：** 撤銷簽發者將立即使其名下所有有效 DIT 失效，於二進位層建立硬性時序截斷。

### 3.3 L3：動態資訊流控制與帶內遮蔽 (Dynamic IFC & Redaction)
L3 實作記憶體內污染追蹤與帶內機密遮蔽。當機密資產流經 Agent 上下文時，L3 於資料離開受控行程邊界前進行即時遮蔽（替換為 `[REDACTED_BY_DROS_POLICY_GATE]`），杜絕 Prompt 側信道外洩。

### 3.4 L4：二進位 C-ABI 授權執行閘門 (Execution Gate)
L4 為受控之二進位授權邊界，採用記憶體安全之 Rust 語言實作並透過純 C-ABI 動態庫導出。所有受管轄的工具調用均必須跨越此閘門：
1. **$O(1)$ 常數時間策略查表：** 能力檢查透過 64 位元點陣圖常數時間運算完成。
2. **RCU 狀態撤銷與寬限期語意 ($T_{\text{swap}} \approx 420\text{ ns}$)：** 能力指針透過 `AtomicPtr.swap(&P_act, P_new, Ordering::Release)` 進行線性化切換。切換完成後新進入之請求立即觀察到新世代策略；切換前已進入臨界區之舊請求受嚴格紀元寬限期（Grace Period）協議約束並安全退役。
3. **亞微秒級 Fail-Closed 拒絕路徑 ($<500\text{ ns}$)：** 任何不匹配的調用立即進入記憶體內硬拒絕分支，阻止執行抵達 OS 系統呼叫介面。

## 四、 漸進式對抗評測框架與實證數據

### 4.1 證偽導向之評測哲學 (Falsification-Oriented Evaluation)
傳統資安評測常依賴被動式測試套件以確認系統在預期條件下正常運作。DROS-VEP 則明確圍繞**對抗證偽（Adversarial Falsification）**構建：每一個評測層級均被視為一次尋找破壞核心安全不變量之可執行反例（Counterexample）的嚴密嘗試。`PASS` 判定不代表在全宇宙中不可能存在反例，而是代表在數百萬次變異、併發壓力與自主生成的攻擊中，**於受控狀態空間內未觀測到任何反例**。

```text
Level 1: 基準校準 ── 建立功能正確性與 B0 破防 (ΔS_B0 > 0)
   ↓
Level 2: 自主對抗搜尋 ── Strix 白箱自適應搜尋 (最大化物理效應)
   ↓
Level 3: 動態壓力與混沌 ── 100-Agent 拓撲、RCU 競態、故障注入
   ↓
Level 4: 元驗證 ── 負向控制組 (蓄意破壞二進位檔) 與 100 個變異體
   ↓
Level 5: Oracle 獨立性 ── 四階段 Ground-Truth 流水線 (意圖 → 授權 → 執行 → 效應)
   ↓
Level 6: 平台可攜性 ── 跨 x86_64、aarch64、glibc、musl、MSVC 策略可攜性驗證
   │
   └─► 開放證偽層 (外部可重現性套件與公開反例庫)
```

| **L6 可攜** | 跨 OS 與硬體架構驗證 | 7,500 個自動化測試向量 | 於 x86_64、ARM64、Windows、Linux 驗證 | **0** | **PASS** |

### 4.2 24 小時長效浸泡壓力實證 (24-Hour Soak Evidence)
在開源 DROS-VEP-lite 環境中執行的 24 小時連續浸泡評測共處理 **160,611 次獨立請求**（跨越核心場景與 B2B 供應鏈 ATS-001–ATS-004）。其中 **137,751 次惡意請求於 C-ABI 邊界達成 100% 阻絕**。中位數決策延遲鎖定在 $26.21\ \mu\text{s}$（$\sigma = \pm 0.34\ \mu\text{s}$），二進位拒絕延遲低於 $500\text{ ns}$，24 小時常駐記憶體增長為 **0 MB**。對照切換 `BYPASS_GUARD` 證實相同攻擊在 B0 下持續引發未受管狀態轉變，在 B1 下達成完全遏制。

### 4.3 變異測試與負向控制 (Mutation Score - RQ3)
為回答 **RQ3**，我們構建了 5 個蓄意植入缺陷的被破壞二進位檔，並在 8 大變異類別中評估 100 個變異體。評測基座達成 **Mutation Score = 1.0 (100% 變異體殺死率)**，證明測試基座具備極高敏銳度，絕非橡皮圖章。

## 五、 四階段解耦 Oracle 與實證數據

### 5.1 四階段獨立 Ground-Truth 流水線 (RQ4)
貫徹**「任何單一組件不得作為自身唯一證人」**之原則，DROS-VEP 建立四階段解耦流水線：

$$\text{意圖 Oracle } (O_I) \longrightarrow \text{授權 Oracle } (O_A) \longrightarrow \text{執行 Oracle } (O_E) \longrightarrow \text{物理效應 Oracle } (O_P)$$

#### 方法學依據：主張與證據的徹底解耦
在單體式資安評測中，授權子系統通常自行記錄決策，造成循環驗證漏洞：若授權引擎崩潰或被繞過，其內部日誌可能錯誤宣稱未發生違規。透過將觀測分解為四個獨立觀察者，DROS-VEP 保證了客觀的交叉驗證：
1. **意圖 Oracle ($O_I$)：** 於任何正規化之前，直接自調用端行程記錄原始 Payload。
2. **授權 Oracle ($O_A$)：** C-ABI 閘門評估點陣圖並發出數位簽名之 ALLOW/DENY 決策。
3. **執行 Oracle ($O_E$)：** 獨立核心追蹤器（eBPF / ProcFS）監控是否有任何實際 Syscall 進入 OS 核心，確認 $G = 0$ 幽靈 Syscall。
4. **物理效應 Oracle ($O_P$)：** 頻外資料庫 WAL、檔案系統 Diff 與行程樹雜湊比對確認 $S_{\text{after}} \equiv S_{\text{before}}$。

四個解耦 Oracle 之間的一致判定，提供了獨立的經驗證據，證明授權決策在受控觀測邊界內確實產生了所觀測到的物理遏制效果。

### 5.2 物理副作用遏制率 ($\Delta I_{\text{physical}}$ - RQ1)
$$\Delta I_{\text{physical}} = I_{\text{physical}}(B0) - I_{\text{physical}}(B1) = 1.0 - 0.0 = \mathbf{1.0\ (100\%\ 物理抑制率)}$$

### 5.3 效能與延遲開銷
在 AMD Ryzen 9 7950X / Ubuntu 24.04 實體機評測（並在 Intel Xeon E3-1275L v3 上獲得一致驗證）：
* **端到端決策延遲 (P50)：** $26.1\ \mu\text{s}$
* **端到端決策延遲 (P99)：** $31.4\ \mu\text{s}$（隔離路徑）/ $242.7\ \mu\text{s}$（50 執行緒高併發浸泡）
* **RCU 狀態指針原子切換 ($T_{\text{swap}}$)：** $420\text{ ns}$
* **L4 Fail-Closed 拒絕路徑延遲：** $<500\text{ ns}$

## 六、 開放證偽協議與局限性說明

### 6.1 局限性與認識論邊界 (Limitations & Epistemic Scope)
1. **本體論依賴：** DROS 依賴於 L2 DIT 中能力點陣圖的正確映射；若給予未受信任角色過高特權，屬於政策配置錯誤，而非基板逃逸。
2. **觀測邊界限制：** 零反例結論嚴格受限於實驗實例化之狀態空間（逾 60,000 次探針、160,611 次浸泡請求、100-Agent 網格），不構成跨越無限攻擊宇宙的先驗絕對證明。
3. **可攜性 vs. 原生核心邊界：** L6 驗證政策配置之跨平台可攜性；原生核心層級的強制執行仍受限於宿主 OS MMU 與核心驅動程式之完整性。

### 7.1 LLM 語意護欄 vs. 執行期遏制
NVIDIA NeMo Guardrails 與 Meta LlamaGuard 等應用層護欄在執行前檢查自然語言與參數。儘管在毒性過濾與合規對齊上非常有效，但其運作本質上屬於概率性分類。一旦 Agent 遭受間接注入或直譯器逃逸攻破，語意防火牆無法阻止未授權 Syscall，因為攻擊者是從已驗證的行程內部發起操控。DROS 將語意過濾視為可選的 L1 層，並將硬性安全保證委託給二進位 C-ABI 邊界（L4）。

### 7.2 作業系統核心沙箱與上下文失明
Linux Seccomp-BPF、Landlock 與 gVisor 等核心機制對系統呼叫提供剛性二進位約束。然而，它們面臨「上下文失明問題」：核心僅觀察 PID 與 UID。在多個 Agent 角色於共享行程中運行的多代理人架構中，核心沙箱無法分辨資料庫查詢是由合法的財務 Agent 還是遭劫持的客服 Agent 所發起。DROS 透過在 FFI 邊界直接驗證包含已簽署點陣圖的 DIT，成功弭平此歸因斷層。

### 7.3 動態資訊流控制與帶內遮蔽
TaintDroid 與 Flume 等動態資訊流控制（IFC）系統追蹤機密資料在暫存器與記憶體中的傳播。DROS 將經典 IFC 概念轉化為 L3 層的記憶體內污染追蹤與帶內機密遮蔽，於資料離開受控上下文前進行替換，在極低效能開銷下杜絕 Prompt 側信道外洩。

### 7.4 能力基礎存取控制與零信任工作負載身分
經典能力系統（Dennis and Van Horn、Levy）將特權與不可偽造的 Token 關聯。在雲端原生架構中，SPIFFE/SPIRE 與 NIST SP 800-207 提供密碼學工作負載身分認證。DROS 將能力理論延伸至自主 Agent，將動態權限編譯為 64 位元能力點陣圖並簽發 DIT。透過 RCU 原子狀態指針切換，達成亞微秒級策略撤銷，將零信任身分與微秒級執行強制執行無縫銜接。
